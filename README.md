### Keenetic WG Watchdog

Удалённое восстановление WireGuard между роутерами Keenetic.

## Схема работы

Программа ставится на центральный Keenetic с Entware, который принимает
WireGuard-подключения. Удалённому Keenetic Entware не нужен.

Центральный роутер проверяет адрес выбранного пира внутри туннеля. После двух
последовательных ошибок он подключается к HTTP RCI API удалённого Keenetic по
независимому адресу и перезапускает там только указанный `WireguardN`.

## Важно

Адрес управления удалённым Keenetic не должен проходить через контролируемый
туннель. После команды `down` этот путь исчезнет и команда `up` не дойдёт.

Подойдёт прямой HTTPS-доступ через внешний адрес и отдельный порт, KeenDNS или
CrazeDNS в режиме **«Прямой доступ»**, отдельная управляющая VPN либо служебная
сеть. Доступ следует ограничить IP-адресом центрального роутера. Облачный режим
KeenDNS/CrazeDNS для этой версии не подходит.

## Возможности

- интерфейс в стиле WG Watchdog Manager;
- последовательный выбор локального WG-сервера и его пира;
- определение адреса контроля из `allow-ips /32` или `/128`;
- проверка авторизации и наличия удалённого интерфейса при настройке;
- две ошибки до перезапуска, контроль восстановления и cooldown 30 минут;
- три попытки вернуть удалённый интерфейс в `up`;
- отдельные задания для разных интерфейсов и пиров;
- пароли хранятся в конфигурациях с правами `600`;
- работа через cron без Python, systemd и программ на удалённом Keenetic.

## Требования

- центральный Keenetic с установленным Entware;
- KeeneticOS с WireGuard;
- прямой доступ к RCI API удалённого Keenetic;
- на удалённом Keenetic — отдельная учётная запись администратора.

Установщик проверяет и при необходимости добавляет `ndmq`, `curl` и `cron`.

## Настройка удалённого Keenetic-клиента

На удалённый роутер устанавливать Entware или сам watchdog не нужно. От него
требуются только доступный интерфейс WireGuard и независимый HTTPS-доступ к
веб-конфигуратору/RCI API.

### 1. Подготовьте учётную запись

В веб-интерфейсе удалённого роутера откройте раздел пользователей и создайте
отдельного пользователя для watchdog:

- задайте длинный уникальный пароль;
- предоставьте права администратора — без них изменить состояние интерфейса
  WireGuard не получится;
- не используйте эту учётную запись для обычного входа в роутер.

Название раздела зависит от версии KeeneticOS/NetcrazeOS: обычно это
**«Пользователи и доступ»** или **«Управление → Пользователи»**.

### 2. Выберите адрес управления

| Вариант | URL в настройках `kwg` | Условия |
|---|---|---|
| Публичный IP или обычный DDNS | `https://203.0.113.10:8443` или `https://router.example.net:8443` | Прямой HTTPS-доступ к роутеру |
| KeenDNS | Например, `https://branch.keenetic.pro` | Только режим **«Прямой доступ»** |
| Netcraze CrazeDNS | Точный HTTPS-адрес, показанный в разделе CrazeDNS | Только режим **«Прямой доступ»** |
| Управляющая VPN/служебная сеть | Например, `https://10.20.0.2` | Маршрут не должен зависеть от перезапускаемого WG-туннеля |

Для KeenDNS откройте страницу **«Доменное имя»**, зарегистрируйте имя и выберите
режим **«Прямой доступ»**. Для роутеров Netcraze выполните те же действия в
разделе **CrazeDNS**. В `kwg` вводите адрес целиком так, как он показан роутером,
но без `/auth`, `/rci` и завершающего пути.

Режим **«Прямой доступ»** требует публичного («белого») IP-адреса со стороны
провайдера. Само доменное имя лишь отслеживает этот адрес и не обходит CGNAT.
Разрешите HTTPS-доступ к веб-конфигуратору на WAN-интерфейсе и, по возможности,
ограничьте его в межсетевом экране публичным IP центрального роутера.

> **KeenDNS/CrazeDNS «Через облако» не поддерживается.** В этом режиме запросы
> проходят через облачный веб-прокси, а watchdog не получает заголовки
> `X-NDM-Realm` и `X-NDM-Challenge`, необходимые для авторизации в RCI API.
> Открытие веб-интерфейса в браузере ещё не означает, что API будет доступен.
> Если у клиента серый IP, используйте отдельную управляющую VPN, служебную сеть
> или иной прямой маршрут, не проходящий через контролируемый WireGuard-туннель.

### 3. Запомните имя интерфейса

На удалённом роутере определите системное имя нужного туннеля: `Wireguard0`,
`Wireguard1` и т. д. Именно это имя, с учётом регистра, нужно указать в `kwg`.
После сохранения задания менеджер проверит авторизацию и наличие интерфейса до
включения мониторинга.

## Установка

```sh
wget -qO- https://raw.githubusercontent.com/org1org/keenetic-wg-watchdog/main/install.sh | sh
```

Затем:

```sh
kwg
```

Менеджер сначала покажет локальные интерфейсы `WireguardN`, затем пиры выбранного
интерфейса. Для задания нужно указать:

- туннельный адрес пира;
- независимый URL управления удалённым Keenetic;
- логин и пароль;
- системное имя удалённого туннеля (`Wireguard0`, `Wireguard1` и т. д.).

## Управление

В меню настроенного пира доступны проверка сейчас, принудительный перезапуск,
изменение настроек, включение/выключение и удаление задания.

События записываются в системный журнал Keenetic с тегом
`keenetic-wg-watchdog`.

## Удаление

```sh
wget -qO- https://raw.githubusercontent.com/org1org/keenetic-wg-watchdog/main/install.sh | sh -s -- --uninstall
```

Настройки сохраняются в `/opt/etc/keenetic-wg-watchdog.d`.
