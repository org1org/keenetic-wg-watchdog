### Keenetic WG Watchdog

Удалённое восстановление WireGuard между роутерами Keenetic.

## Схема работы

Программа ставится на центральный Keenetic с Entware, который принимает
WireGuard-подключения. Удалённому Keenetic/Netcraze Entware не нужен, и он может
находиться за NAT с серым IP-адресом.

Центральный роутер проверяет адрес выбранного пира внутри туннеля. После двух
последовательных ошибок он подключается к HTTP RCI API удалённого Keenetic по
облачный HTTP Proxy KeenDNS/CrazeDNS и перезапускает там только указанный
`WireguardN`.

## Важно

Адрес управления удалённым Keenetic не должен проходить через контролируемый
туннель. После команды `down` этот путь исчезнет и команда `up` не дойдёт.

Основной вариант — отдельный домен 4-го уровня KeenDNS/CrazeDNS в режиме
**«Через облако»**, направленный на HTTP Proxy роутера. Такой путь сохраняется
при перезапуске WireGuard и работает за CGNAT. Прямой RCI-доступ также
поддерживается как запасной вариант.

## Возможности

- интерфейс в стиле WG Watchdog Manager;
- облачная Digest-авторизация KeenDNS/CrazeDNS как основной режим;
- автоматический fallback на прямую RCI-авторизацию;
- последовательный выбор локального WG-сервера и его пира;
- поддержка блочного и вложенного формата конфигурации WireGuard в разных
  версиях KeeneticOS/NetcrazeOS;
- определение адреса контроля из `allow-ips /32` или `/128`;
- проверка авторизации и наличия удалённого интерфейса при настройке;
- две ошибки до перезапуска, контроль восстановления и cooldown 30 минут;
- три попытки вернуть удалённый интерфейс в `up`;
- отдельные задания для разных интерфейсов и пиров;
- пароли хранятся в конфигурациях с правами `600`;
- работа через cron без Python, systemd и программ на удалённом Keenetic.

## Требования

- центральный Keenetic с установленным Entware;
- KeeneticOS с WireGuard;
- настроенный облачный HTTP Proxy KeenDNS/CrazeDNS на удалённом роутере;
- на удалённом роутере — отдельный пользователь с нужными правами.

Установщик проверяет и при необходимости добавляет `ndmq`, `curl` и `cron`.

## Настройка удалённого Keenetic-клиента

На удалённый роутер устанавливать Entware или сам watchdog не нужно. API штатно
публикуется через облачный HTTP Proxy KeenDNS/CrazeDNS и остаётся доступным при
сером IP-адресе.

### 1. Подготовьте учётную запись

В веб-интерфейсе удалённого роутера откройте раздел пользователей и создайте
отдельного пользователя для watchdog:

- задайте длинный уникальный пароль;
- предоставьте права администратора — без них изменить состояние интерфейса
  WireGuard не получится;
- не используйте эту учётную запись для обычного входа в роутер.

Название раздела зависит от версии KeeneticOS/NetcrazeOS: обычно это
**«Пользователи и доступ»** или **«Управление → Пользователи»**.

### 2. Опубликуйте RCI API через облако

В разделе **«Доменное имя»** зарегистрируйте KeenDNS или CrazeDNS в режиме
**«Через облако»**. Затем добавьте домен 4-го уровня со следующими параметрами:

| Поле | Значение |
|---|---|
| Имя | `rci` или другое свободное имя |
| Доступ из интернета | **Авторизованный доступ** |
| Устройство | **Это устройство Keenetic** |
| Протокол | **HTTP** |
| Порт TCP | `79` |
| Пользователи | Добавьте только созданного пользователя `wgwatchdog` и отметьте ему доступ |

Для поля **«Доступ из интернета»** доступны три варианта:

- **Авторизованный доступ** — нужный и рекомендуемый вариант. Облачный прокси
  запросит логин и пароль посредством Digest-аутентификации;
- **Свободный доступ** — технически работает без авторизации, но открывает RCI
  API роутера любому пользователю интернета. Не используйте этот вариант;
- **Нет доступа** — полностью закрывает домен, поэтому watchdog подключиться не
  сможет.

Не предоставляйте доступ пользователю `admin`, если он не используется
watchdog. В списке пользователей достаточно отметить только отдельную учётную
запись `wgwatchdog`.

В результате получится отдельный адрес API:

- KeenDNS: `http://rci.branch.keenetic.pro`;
- CrazeDNS: например, `http://rci.branch.netcraze.pro`.

Суффикс домена может отличаться — скопируйте полный адрес из веб-интерфейса.
В `kwg` указывается только базовый адрес без `/auth`, `/rci` и других путей.
Главный адрес веб-интерфейса вида `https://branch.keenetic.pro` для облачного API
не подходит: требуется именно отдельный домен, проксируемый на порт `79`.

Watchdog сначала выполняет запрос с Digest-аутентификацией. Логин и пароль не
передаются в открытом виде и не помещаются в аргументы процесса `curl`. Если
сервис предоставляет HTTPS-вариант RCI-домена, используйте его: сертификат в
облачном режиме проверяется. Для прямого подключения программа автоматически
переключится на обычную RCI-авторизацию Keenetic.

Официальные инструкции:

- [Keenetic: Using API methods through the HTTP Proxy service](https://support.keenetic.com/starter/kn-1121/en/55035-using-api-methods-through-the-http-proxy-service.html);
- [Netcraze: Применение методов API через службу HTTP Proxy](https://support.netcraze.ru/giga/nc-1012/ru/55035-using-api-methods-through-the-http-proxy-service.html).

### 3. Запомните имя интерфейса

В веб-интерфейсе удалённого роутера нажмите **шестерёнку → «Командная строка»**
и выполните:

```text
show interface
```

Найдите нужный WireGuard-туннель по его описанию и запомните системное имя:
`Wireguard0`, `Wireguard1` и т. д. Если по выводу определить туннель сложно,
выполните:

```text
show running-config
```

Каждый туннель начинается со строки `interface WireguardN`, а ниже обычно
указано его описание. Именно имя `WireguardN`, с учётом регистра, нужно ввести
в `kwg`. После сохранения задания менеджер проверит облачную авторизацию и
наличие интерфейса до включения мониторинга.

### Обновление с 0.1.0

Повторно запустите установщик, затем откройте `kwg`, выберите существующее
задание и пункт **«Изменить настройки»**. Замените прежний адрес управления на
домен 4-го уровня `http://rci.…`, настроенный на порт `79`. Остальные параметры
задания сохранятся.

## Установка

```sh
wget -qO- https://raw.githubusercontent.com/org1org/keenetic-wg-watchdog/main/install.sh | sh
```

Затем:

```sh
kwg
```

Менеджер сначала покажет локальные интерфейсы `WireguardN`, затем пиры выбранного
интерфейса. Для задания нужно указать:

- туннельный адрес пира;
- облачный RCI URL удалённого Keenetic/Netcraze;
- логин и пароль;
- системное имя удалённого туннеля (`Wireguard0`, `Wireguard1` и т. д.).

## Управление

В меню настроенного пира доступны проверка сейчас, принудительный перезапуск,
изменение настроек, включение/выключение и удаление задания.

События записываются в системный журнал Keenetic с тегом
`keenetic-wg-watchdog`.

## Удаление

```sh
wget -qO- https://raw.githubusercontent.com/org1org/keenetic-wg-watchdog/main/install.sh | sh -s -- --uninstall
```

Настройки сохраняются в `/opt/etc/keenetic-wg-watchdog.d`.
